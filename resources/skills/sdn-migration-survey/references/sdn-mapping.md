# 现网业务分析维度 → 新建 SDN 网络推荐方案

做阶段二业务分析时，用户描述一个老网络现状，就对照本表给出对应的 SDN（CloudFabric）推荐方案。

## 1. 网络架构

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| 组网架构 | 单 DC 内组网、主备 DC | DC 内：Spine-Leaf 架构；主备 DC / 多 DC 互通：multi-pod 或 multi-site |
| 网络扩展性 | 当前业务规模 + 未来扩展需求 | 按未来 5~10 年扩展需求选可演进架构，优先推荐 Border Leaf、Service Leaf、Spine **角色分设** |
| 网络性能 | 当前上下行收敛比及演进需求 | 按业务需求选合适收敛比。注：与 Spine 互联的上行口**不建议用低速率端口**，避免严重微突发影响性能 |
| 网络协议 | ALL | 大二层隧道：BGP EVPN + VXLAN；Underlay 路由：OSPF、eBGP；可靠性：M-LAG、BFD |

## 2. 流量模型

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| 流量类型 | 单播 | 只有单播业务的 VPC 按 SDN 方案部署 |
| 流量类型 | 组播 | 涉及组播的 VPC 按实际诉求、方案与设备款型满足度，选 Overlay 组播或 Underlay 组播 |
| IP 协议栈 | IPv4 单栈 | 按 IPv4 单栈规划部署 |
| IP 协议栈 | IPv4 & IPv6 双栈 | 按双栈场景规划部署 |
| IP 协议栈 | IPv6 单栈 | 按 IPv6 单栈规划部署 |
| 网关位置 | 网关在 Fabric 内交换机上 | 网关在 Server Leaf 上 |
| 网关位置 | 网关在 FW 上 | 方案一：继承老模型，网关仍在 FW，VXLAN 提供二层隧道；方案二：网关改到 Server Leaf。流量模型复杂或非华为 FW 且需利旧时，**优先方案一** |
| 网关位置 | 网关在 LB 上 | 方案一：继承老模型，网关仍在 LB，VXLAN 提供二层隧道；方案二：网关改到 Server Leaf。流量模型复杂时**优先方案一** |
| 网关位置 | 网关在外部 PE 上 | 方案一：继承老模型，网关仍在 PE，VXLAN 提供二层隧道；方案二：网关改到 Server Leaf。流量复杂优先方案一；有控制器自动化配三层网络需求时推荐方案二 |

## 3. 业务互访关系

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| 子网内主机互访 | 经过 FW 安全策略控制 | SDN 编排业务链将流量引向 FW |
| 子网内主机互访 | 不经过 FW 且不需隔离 | SDN 编排 VPC |
| 子网内主机互访 | 不经过 FW 但需隔离 | SDN 编排业务链 |
| 子网内主机互访 | 同一服务器内 VM 间需 Server Leaf 二层隔离 | SDN 编排业务链且配置 pvlan，需 vCenter 侧配合设置专用 VLAN |
| VPC 内子网间互通 | 经过 FW 安全策略控制 | SDN 编排业务链将流量引到 FW |
| VPC 内子网间互通 | 不经过 FW 且不需三层隔离 | SDN 编排 VPC |
| VPC 内子网间互通 | 不经过 FW 但需三层隔离 | SDN 编排业务链，策略为 deny |
| 跨 VPC 互通 | 经过 FW | SDN 编排经过 FW 的 VPC 互通 |
| 跨 VPC 互通 | 不经过 FW | SDN 编排不经过 FW 的 VPC 互通 |
| 出口网络 | VPC 多个出口 | SDN 创建多个外部网关，VPC 关联外部网关 |
| 出口网络 | 两个 Fabric 主备出口 | SDN 用 Multi-POD 或 Multi-Site（MDC）方案编排主备出口外部网关 |
| 出口网络 | 出口路由主备路径 | SDN 外部网关路由可靠性方案同老网络，配置路由主备路径 |
| 出口网络 | 南北向流量过墙 | SDN 编排 VPC，关联 Logical VAS |
| 出口网络 | 南北向流量不过墙 | SDN 编排 VPC，不关联 Logical VAS |

## 4. 服务器接入

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| 网卡可靠性 | 网卡主备方式捆绑 | 网卡主备方式捆绑 |
| 网卡可靠性 | 网卡负载分担捆绑，LACP 对接 | 网卡负载分担捆绑，LACP 对接 |
| 网卡可靠性 | 网卡单链路接入不捆绑 | 服务器/应用侧无可靠性时，搬迁会长时间流量中断，**建议优先评估接入可靠性** |
| 主机接入类型 | 虚拟机 / 物理机裸金属 / 容器 | 对应：虚拟机 / 物理机裸金属 / 容器 |
| 接入业务类型 | 电信云场景运营商核心网网元 | 按电信云场景 SDN 方案能力评估 |
| 接入业务类型 | 私有云场景主机接入 | 按需部署：容器 L3 接入（Server Leaf 与容器对接路由协议）；容器和虚拟机 L2 接入（Server Leaf 提供网关）；物理机/裸金属 L2 接入（Server Leaf 提供网关） |
| 是否有 NLB | NLB 服务器是否跨 TOR 部署 | 若有 NLB，需 NLB 服务器**不跨 TOR** 部署，且部分配置需手工部署 |
| VMM 对接 | VMM 型号、软件版本、是否跨 VMM 迁移、开启的功能、SDN 是否支持对接 | 条件满足用计算联动方案；不满足建议 VMM 与控制器**不联动** |

## 5. VAS 接入

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| VAS 接入方式 | Eth-Trunk 双归接入 | Border Leaf、Service Leaf 部署 M-LAG 与 VAS 对接 |
| VAS 接入方式 | 一组 VAS 两台成员接入不同站点 | Border Leaf、Service Leaf 部署 M-LAG 与 VAS 对接 |
| VAS 类型 | 梳理有哪些 VAS、接入模型 | ① Fabric 内部 LB、第三方 FW：控制器通过哑设备方式编排；② Fabric 内部 DDoS、WAF：优先部署在网络出口 |

## 6. DCI 互通

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| DCI 互通 | 二层互通的 VLAN；三层互通的 VPN、子网；是否经过防火墙 | 根据互通需求选合适的 DCI 方案 |

## 7. 业务量评估

| 分析维度 | 老网络现状 | SDN 推荐方案 |
|---------|-----------|------------|
| 转发表项 | ARP、ND、FIB、FIBv6、SG 数量（含 Fabric 内部服务器与外部 Fabric 学习到的表项）；VPN、VLANIF、VLAN 数量 | ① 按 CloudFabric 叠加规格，评估 SDN 设备规格是否满足；② 若有利旧交换机，评估搬迁中间态对利旧交换机的资源需求 |
| ACL | ACL 数量、ACL 资源 | 按老网络隔离需求、特性叠加需求，评估 SDN 设备 ACL 数量、slice 是否满足 |
