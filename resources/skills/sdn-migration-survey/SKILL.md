# 数据中心搬迁到 SDN — 现网采集引导

## 这个 skill 做什么

帮用户把一个**新的 DC→SDN 搬迁项目**在"搬迁前准备"阶段必须完成的两件事做扎实：

1. **现网信息采集** —— 摸清现网家底（9 个信息维度）
2. **现网业务分析** —— 在家底之上做业务梳理、协议兼容性判断、SDN 方案映射

只有这两步采集齐全、且关键卡点都有明确结论，项目才能进入下一节（SDN 目标模型设计 / 迁移方案制定）。本 skill 的终点是产出一份**采集汇总 + 准入判断**。

## 工作方式：交互式问答推进，而不是甩一张空表

用户要的是被"带着走"，不是收到一张 30 行的空表自己填。所以：

- **分组追问，不要一次问完。** 把采集项拆成若干逻辑组，一组一组问。每组先说清"这组要确认什么、为什么重要"，再提具体问题。一次提问控制在一组之内，避免信息过载。
- **能从材料里读出来的，就不要问。** 如果用户已经提供了 HLD/LLD、配置文件、`show` 命令回显、拓扑图，先自己读取并提取，把提取到的值回填进采集表，只就**读不出来或有歧义**的项向用户确认。这是省用户时间最关键的一点。
- **边问边维护一份"采集进度"。** 每完成一组，回显一个小结：已采集 / 待补充 / 有风险。让用户随时知道还差什么。
- **遇到协议和业务模型，要现场给判断，不要只记录。** 用户报上来一个协议（如 HSRP、FabricPath、EIGRP），立刻查 `references/protocol-compatibility.md` 告诉他兼容性和推荐对接方案；用户描述一个业务现状（如网关在 FW 上），立刻查 `references/sdn-mapping.md` 给出 SDN 侧推荐方案。采集和分析是一体的。

## 整体流程

```
触发 → 开场对齐 → 阶段一:现网信息采集(9维度) → 阶段二:现网业务分析(协议+维度)
     → 采集进度小结 → 准入判断(Gate) → 产出采集汇总文档(可选)
```

### 开场对齐（第一条回复就做）

简短说明：这是搬迁前准备的第一步，我们会按两个阶段把现网信息收集齐，过程中我会逐组提问、能从你给的材料里读的就不重复问。然后问两个开场问题：

1. **有没有现成材料可以先给我？**（HLD/LLD 方案、设备配置文件、拓扑图、`show` 回显、VMM 清单等）——有就先读，能回填多少回填多少。
2. **现网是什么厂家/架构起步的？**（如 Cisco vPC+HSRP、Cisco ACI、华为/友商 M-LAG、SVF、FabricPath 等）——这决定了后面协议对接的重点，也对应迁移方案里的不同场景。

## 阶段一：现网信息采集（9 个维度）

逐组确认下列 9 个维度。括号里是"为什么要"，用来向用户解释、也帮你判断哪些项可以从材料里直接读取。建议按 3 组节奏推进，避免一次问太多。

**组 A · 网络本体（方案 / 设备 / 配置 / 版本）**
1. **方案组网**：HLD、LLD 方案文档 —— 了解网络方案与部署架构。
2. **设备款型**：设备厂家、型号 —— 掌握现网实际款型（决定可利旧范围与对接能力）。
3. **配置文件**：所有设备的完整配置（路由协议、单/双栈、组播等）—— 了解现网实际开启了哪些功能。
4. **软件版本**：现网产品软件版本，含 VMM（vCenter / OpenStack 等）、利旧 FW/LB 的软件版本 —— 用于搬迁后对接分析。

**组 B · 规格与协议（表项 / 路由 / 业务模型）**
5. **业务表项**：MAC / ARP / ND / FIBv4 / FIBv6 / SG / ACL 的数量 —— 评估搬迁后业务对新网络的规格需求。
6. **路由协议**：交换机与 PE、VAS（FW / LB / WAF 等安全设备）的对接协议 —— 决定对接方案。
7. **业务模型**：VPN 数量、VLAN 数量、IP 网段数量、流量模型、通信矩阵 —— 容量与模型规划基础。

**组 C · 接入与性能**
8. **接入侧**：接入类型（物理机 / 虚拟机 / 容器 / 存储）、接入方式（网卡主备捆绑 / 负载分担捆绑）、接入对接协议（LACP / BGP / ECN / PFC）—— 接入侧迁移设计。
9. **性能**：现网流量高峰带宽、网络最大带宽、故障倒换收敛时间、升级业务中断时间 —— 作为搬迁后必须守住的 SLA 基线。

每组结束后回显已采集值与缺口，再进入下一组。

## 阶段二：现网业务分析

在阶段一基础上做"梳理 + 判断"，分两部分。

### 2.1 网络协议对接类型

请用户列出现网在用的二层协议、链路捆绑、路由协议、HA 协议。每报一个，就查 `references/protocol-compatibility.md`，当场给出：华为侧对应协议、兼容性、推荐对接方案。

需要逐项确认是否使用：
- **二层协议**：PVST / PVST+、MSTP、FabricPath、CDP、VXLAN
- **链路捆绑**：跨设备链路聚合（vPC 等，对端 M-LAG）
- **路由协议**：EIGRP、OSPF、BGP
- **HA 协议**：HSRP / VRRP

> 重点提示用户：生成树类、FabricPath、CDP、EIGRP、HSRP 多数**不建议**新老两网直接对接，需提前决定 hand-off 或协议切换方案——这往往是搬迁方案里最先要拍板的事。

### 2.2 业务分析维度

按下列 7 个维度，逐项采集"老网络现状"，并对照 `references/sdn-mapping.md` 给出"新建 SDN 网络推荐方案"。这是把现网业务翻译成 SDN 编排模型的核心。

1. **网络架构**：组网架构（单 DC / 主备 DC / 多 DC 互通）、网络扩展性（当前规模 + 未来 5~10 年扩展需求）、网络性能（上下行收敛比及演进需求）、网络协议。
2. **流量模型**：流量类型（单播 / 组播）、IP 协议栈（IPv4 单栈 / 双栈 / IPv6 单栈）、**网关位置**（Fabric 交换机 / Server Leaf / FW / LB / 外部 PE）。
3. **业务互访关系**：子网内主机互访、VPC 内子网间互通、跨 VPC 互通、出口网络——每一类都要区分**是否过 FW、是否需要隔离**。
4. **服务器接入**：网卡可靠性（主备 / 负载分担 LACP / 单链路）、主机接入类型（虚拟机 / 物理机裸金属 / 容器）、接入业务类型（电信云 / 私有云）、是否有 NLB 及是否跨 TOR、VMM 对接（型号、版本、是否跨 VMM 迁移、开启功能、SDN 是否支持对接）。
5. **VAS 接入**：VAS 接入方式（Eth-Trunk 双归 / 跨站点）、VAS 类型（LB / 第三方 FW / DDoS / WAF 及其接入模型）。
6. **DCI 互通**：二层互通的 VLAN、三层互通的 VPN / 子网、是否经过防火墙。
7. **业务量评估**：转发表项（ARP / ND / FIB / FIBv6 / SG 数量，含内外部学习到的表项 + VPN / VLANIF / VLAN 数量）、ACL（数量及资源 / slice 占用）。

> 网关位置（维度 2）和业务互访是否过墙（维度 3）通常牵一发动全身，遇到要重点和用户确认清楚。

## 采集进度小结

任何时候用户问"还差什么"，或每完成一个阶段，输出一个三列小结：

| 采集项 | 状态（已采集 / 待补充 / 风险） | 值 / 备注 |

把"待补充"和"风险"项排在前面，方便用户优先处理。

## 准入判断（Gate）—— 能否进入下一流程

采集接近完成时，给出明确的准入结论。**下列 4 个关键卡点必须有结论**，否则不建议进入"SDN 目标模型设计"：

1. **协议兼容性已判明** —— 现网每个在用协议是否与华为 SDN 兼容、采用何种方式对接（直接对接 / hand-off / 协议切换），都有结论。
2. **网关位置现状已明确** —— 决定继承老模型还是迁到 Server Leaf。
3. **规格数据齐备** —— 表项（ARP/ND/FIB/FIBv6/SG）与 ACL 数量已采集，可评估 SDN 设备款型，以及利旧交换机在搬迁中间态是否够用。
4. **VMM 型号与版本已确认** —— 决定计算联动是否可行。

输出格式：

```
## 准入判断
- [✅/❌] 协议兼容性已判明：<结论或缺口>
- [✅/❌] 网关位置已明确：<结论>
- [✅/❌] 规格数据齐备：<结论>
- [✅/❌] VMM 型号版本已确认：<结论>

结论：<可进入下一流程 / 暂不可进入，需先补充：xxx>
```

全部 ✅ 才给"可进入"；任一 ❌ 都要列出具体待补项并说明它会卡住后面哪一步。

## 产出采集汇总文档（可选）

如果用户要留档，把整轮采集结果整理成一份 Markdown 文档（阶段一 9 维度表 + 阶段二协议对接表 + 业务分析维度表 + 准入判断），存到项目里用户指定的位置；用户没指定就建议存为 `docs/<项目名>-现网采集.md` 并征求同意后再写。
