# 数据中心数通域新建方案

数据中心网络是传统数据中心的物理基础设施，为金融企业等关键业务提供安全可靠的 IT 服务承载环境。因此，以**高可用网络架构**为核心的数通域方案设计是企业信息化建设的坚实基础。本文围绕银行数据中心数通域设计相关的网络方案。

## **1 背景和概念**

### **1.1 什么是数据中心网络？**

**数据中心（Data Center）**是指集中存放计算资源（如服务器）、存储设备、网络设备及其相关的基础设施（如供电、制冷、消防等系统），以便于管理和处理大量数据的物理场所或设施。数据中心的诞生有以下主要原因：

-   **数据量的爆炸式增长：**随着银行业务数字化的深入和互联网金融的发展，银行产生的交易数据、客户信息、账户数据呈现爆炸式增长。传统分散式的处理方式无法满足大规模数据存储和实时分析的需求，需要一个专业的高标准场所来集中存放和处理这些数据。
    
-   **对计算资源需求的增加：**金融业务的复杂化和实时性要求越来越高，如核心交易系统、支付清算系统、风险管理系统等。这些系统要求有高性能、高可靠的服务器和网络设备，而这些设备的维护和管理需要专业的环境和技术支持，促进了专用数据中心的形成。
    
-   **网络安全与合规要求：**金融行业作为关键基础设施行业，面临严格的安全监管要求。建立符合等级保护标准的数据中心，能够为银行信息系统提供统一的物理安全、网络安全和信息安全防护体系。
    

**数据中心网络**是指在数据中心内部署的网络，用于支持服务器、存储系统和网络设备之间的高速数据交换。它旨在确保高效、可靠的数据传输，并提供对计算资源的快速访问，以满足现代企业应用和服务的需求。数据中心网络是数据中心基础设施的关键组成部分，直接影响到数据中心的整体性能、可用性和可扩展性。数据中心网络具有**高性能、冗余高可用、灵活可扩展**等特点，为了满足这些特点，数据中心的网络架构设计和演进非常重要。

### **1.2 为什么数据中心网络如此重要？**

在数字化转型的时代，数据中心网络已经成为银行核心竞争力的基础支撑。以华为 NE 系列为核心的数据通信网络具备以下显著优势：

-   **高可靠性：**通过设备冗余、链路冗余、协议冗余三层保障机制，实现故障毫秒级切换，确保金融业务连续性。
    
-   **高性能：**采用硬件转发架构，核心层支持 100G/400G 端口密度，满足大数据量交易处理需求。
    
-   **安全性：**内置 ACL、VRF、防火墙等多层次安全防护，符合金融监管合规要求。
    
-   **可管理性：**支持统一网管平台对接，实现自动化运维和智能告警。
    
-   **可扩展性：**模块化设计，支持平滑扩容，适应业务增长需求。

### **1.3 银行数据中心的网络层级**

银行数据中心为了满足不同业务场景和安全需求，将网络进行如下分层设计和抽象管理：

-   **核心层：**数据中心网络的"心脏"，承担全流量的高速转发和跨区调度。
    
    -   每个核心路由器采用 1+1 双机热备，避免单点故障影响整个网络。
        
    -   核心层设计高速互联接口（40G/100G）用于上联互联网出口和下联汇聚层。
        
-   **汇聚层：**承上启下的关键节点，负责区域流量聚合和策略控制。
    
    -   每个汇聚区域采用双机堆叠或 ECMP 负载均衡部署，提高可用性和带宽利用率。
        
    -   汇聚层设计 VRRP 虚拟网关、ACL 访问控制、QoS 策略实施等功能。
        
-   **接入层：**连接终端设备和服务器的边缘网络。
    
    -   根据服务对象不同分为服务器接入区（10GE）和办公终端接入区（1GE/10GE）。
        
    -   接入层设计 PoE+ 供电、端口隔离、环路防护等边缘安全特性。
        
-   **出口安全区：**数据中心与外部世界的边界。
    
    -   部署防火墙、入侵检测系统等安全设备，构建纵深防御体系。
        
    -   设计 NAT、DMZ 区、专线互联等多种对外连接方式。

## 2 本方案目标客户

本方案适用于银行等金融机构新建小型数据中心项目。客户首先需要考虑业务系统如何划分 VLAN/VRF，然后围绕各区域内的网络和区域间互通设计方案。

**网络区域的划分原则：**

**最佳实践是先考虑多 VRF（每个业务类型一个或多个 VRF），原因：**

1. 多个 VRF 间天然划分出多个安全域
2. 多个 VRF 间业务/模块独立，强隔离、弱互通（类似于白名单）
3. 每个 VRF 是一个故障域，故障域小、发生故障后影响范围小
4. 多 VRF 便于财务独立核算和审计追踪
5. 多 VRF 扩展性更好：单 VRF 能做的多 VRF 肯定能做

**特殊情况可以考虑合并 VRF：**

1. 节省跨 VRF 间路由表项开销
2. 单 VRF 内资源好扩展
3. 当业务系统少时，单个 VRF 更好管理
4. 业务容器 POD 混部时，资源利用率更好

### **3.1** **VRF 内网络方案**

【方案概述】VRF 是承载云资源和业务的逻辑容器和平台，VRF 内网络的规划和设计至关重要，它关系到云资源是否安全、后期扩容是否平滑、运维是否方便等问题。从 VRF 选址、IP 地址规划、VLAN 和路由规划、安全防护等角度设计 VRF 内网络。

**1、确定地理位置**

-   根据银行的服务对象所在地区选择机房位置。根据电力供应稳定性、网络线路质量、自然灾害风险等因素选择机房。
    
-   建议同城双活数据中心部署，提升业务连续性。
    

**2、IP 地址规划**

-   VRF 网段：根据未来网络容量大小（超大型 10/8，大型 172.16/12，中型 192.168/16），建议至少选择 16 位掩码
    
-   多 VRF 间地址不能重叠
    
-   VLAN 子网网段：超大型、大型 VRF 建议选择 20 位子网掩码（包含 4K 个地址），中型 VRF 建议选择 24 位子网掩码（包含 252 个地址）

**3、业务 VLAN 交换机**

-   如图中的业务 VLAN A、B、C、D、E，用来放置服务器、存储设备等，这些 VLAN 中的云产品实例私网地址默认全互通
    
-   建议多设备冗余部署、提升可用性，如核心交易 VLAN 与支付清算 VLAN 分别在两个接入设备上部署
    
-   业务 VLAN 交换机，如果没有和公网通信的诉求，为其创建私网路由表（没有默认路由 0.0.0.0/0）并关联
    

**4、入云（被公网访问）连接**

-   如果 VPC 中部署被公网客户端访问的服务系统，建议使用防火墙+NAT
    
-   防火墙实例采用多可用区部署、提升可用性
    
-   为 SLB 实例在多可用区创建交换机和子网
    
-   承接公网访问的服务器关联静态 NAT 或端口映射、连接到公网
    

**5、出云（访问公网）连接**

-   如果 VPC 中部署的服务器有访问公网的需求，建议使用 NAT 网关或防火墙 SNAT
    
-   建议在要出网的服务器所在可用区分别创建 NAT 子网，在这些交换机中都创建 NAT 网关实例、尽量避免跨区域访问 NAT 网关
    
-   在 NAT 网关或防火墙上配置 SNAT 规则（对应要出网的业务 VLAN 或者服务器）
    
-   为要出网的业务 VLAN 创建引流到 NAT 网关的路由表并关联
    

**6、ECS 直通公网**

-   有些应用服务器是随着业务需求随时拉起和释放的、服务端口是随机的；有些应用服务器出网访问需要独立的带宽，避免共用 NAT 网关被其他服务干扰。对于这些服务器不经过 SLB 或 NAT、而是通过静态 NAT 或端口映射更适合。
    
-   某些需要完整 IP 协议支持的应用（FTP、SIP、H.323 等），建议使用一对一静态 NAT 转换
    

**7、IPv4 网关设计【可选&推荐】**

-   当要控制服务器配置公网 IP 时，开启防火墙公网网关功能。所有 VLAN 关联的路由表必须有到防火墙的路由才能去公网
    

**8、安全防护设计【可选】**

-   ACL 可以控制 VLAN 粒度流量阻断，ACL 是无状态的
    
-   安全组可以控制服务器粒度的流量阻断，安全组是有状态的
    

**9、监控和日志记录【可选】**

-   配置 SNMP/Syslog/NTP 进行日常诊断观测，按需使用 flowlog 和流量镜像，并配置对应网管告警
    

**10、容器的 VPC 网络设计类似，区别在于以下几点：**

-   Kube-OVN/Cilium网络插件时，需额外规划Pod网段
    
-   Pod 网段避免与 VRF 地址冲突
    
-   入云连接采用 Ingress Controller 或 LoadBalancer 方式

### **3.2 同 Region 的 VRF 间网络方案**

当部署在不同 VRF 中的业务系统间需要访问时，就需要考虑 VRF 间互通的方案。包括互通与隔离设计，共享服务的访问设计，大型企业公网出入口的统一管控等。

#### **3.2.1 VRF 间东西向互通方案**

【方案概述】VRF 间互通方案，首先要考虑的是谁与谁互通、谁与谁不互通，在不引入防火墙做集中管控的情况下，使用核心路由器的 VRF 表和路由策略可以实现。

**VRF 规划总表：**

| VRF 名称 | 包含 VLAN/业务 | 互通对象 | 备注 |
|----------|---------------|----------|------|
| VRF-Banking | 核心交易、渠道接入、支付清算（VLAN 1001/1002/1003） | 数据仓库、管理网络 | 最高优先级 |
| VRF-Data | 数据仓库、BI 分析（VLAN 1004） | 核心交易、渠道接入 | 中优先级 |
| VRF-DevTest | 开发测试环境（VLAN 1005） | 受限访问生产环境 | 低优先级 |
| VRF-Mgmt | 管理网络（VLAN 2000/2001/2002） | 全部 VRF | 管理平面 |
| VRF-Public | 互联网业务、DMZ 区域（VLAN 1501/1502） | 渠道接入 | 对外业务 |

**1、确定 VRF 的划分**

-   根据前面的 VRF 划分原则进行 VRF 划分，对于通信峰值带宽大的（大于 10Gbps）两个 VRF 考虑进行合并
    

**2、核心路由器实现 VRF 间互通**

-   需要互通的业务 VRF，全部创建连接核心路由器的接口并绑定到对应 VRF
    
-   如果核心路由器挂载的 VRF 之间是强互通诉求，核心只使用一张系统路由表关联转发全部 VRF，来进行 VRF 间的流量转发。见上图 VRF 全互通
    
-   如果核心路由器挂载的 VRF 之间有些是强隔离诉求，核心使用多张自定义路由表关联转发各自 VRF，来进行 VRF 之间的流量转发，同一路由表内的 VRF 可见、不同路由表内的 VRF 间不可见。见上图 VRF 间隔离
    

**3、安全防护设计【可选】**

-   汇聚层 ACL（NACL）可以控制 VLAN 粒度流量阻断，网络 ACL 是无状态的
    
-   接入层安全策略可以控制服务器粒度的流量阻断，安全策略是有状态的
    

**4、监控和日志记录【可选】**

-   配置网管系统进行流量监测、诊断观测
    

#### **3.2.2 VRF 间过防火墙互通方案**

【方案概述】当 VRF 间有复杂的互通与隔离需求时，建议使用防火墙做集中安全管控。

**1、核心路由器实现 VRF 间互通**

-   业务 VRF 和安全 VRF，全部创建连接核心的接口并绑定到对应 VRF
    
-   自定义路由表 1 作为非可信路由表，默认路由 0.0.0.0/0、下一跳到安全 VRF；关联转发全部业务 VRF、将源端业务 VRF 来的流量全部引流到安全 VRF 进而到防火墙实例进行安全清洗
    
-   系统路由表（默认）作为可信路由表，自动学习全部 VRF 的路由；关联转发防火墙 VRF，将防火墙清洗过的流量转发到目的业务 VRF
    

**2、安全 VRF 接入防火墙实现集中安全管控**

-   在此 VRF 内创建防火墙 VLAN 和子网，并在其内创建防火墙实例
    
-   连接核心的接口子网，默认关联到系统路由表
    
-   防火墙实例的接口子网，关联到自定义子网路由表
    
-   系统路由表配置默认路由 0.0.0.0/0、下一跳到防火墙接口，将核心过来的流量全部引流到防火墙
    
-   自定义子网路由表配置默认路由 0.0.0.0/0、下一跳到核心，将防火墙实例清洗过的流量全部送往核心做转发
    

**3、监控和日志记录【可选】**

-   配置网管系统进行流量监测、诊断观测
    

#### **3.2.3 企业服务共享的网络方案**

**访问企业自建的共享服务**

【方案概述】当企业在数据中心内有自建共享服务（如打印机、文档库等）需要被多个业务部门访问时，需要设计服务共享网络。

**1、网络多平面设计**

-   当企业内部各部门（比如开发、测试；财务、HR、行政；等）间网络有强隔离诉求时，使用多个 VRF 做成多个网络平面、每个网络平面之间完全隔离不可见
    
-   每个 VRF 连接各自部门内的 VLAN
    

**2、公共服务 VRF 设计**

-   当有公共服务（企业在 VRF 内自建的，比如打印机）被各个隔离部门访问时，将公共服务部署在公共服务 VRF，此 VRF 分别被各个部门的 VRF 通过路由策略访问
    
-   系统路由表：不要从核心自动学习路由，改为配置自定义路由：到 VRF1 的子网前缀下一跳走接口 2、到 VRFn 的子网前缀下一跳走接口 4
    

**访问银行的云服务/应用**

【方案概述】当企业多个业务部门访问银行原生的云服务/应用（如 RDS、文件存储、API 服务等）时，需要设计访问网络。

**1、公共服务 VRF 设计**

-   划分连接核心的 VLAN 子网
    
-   划分放置 API 网关节点的 VLAN 子网，建议多可用多活冗余
    

**2、业务 VRF 到云服务的访问设计**

-   业务 VRF 和公共服务 VRF 都连接到核心
    
-   业务 VRF 经过核心，通过公共服务 VRF 中的 API 网关节点访问到云服务
    

#### **3.2.4 统一公网出入口方案**

【方案概述】企业客户统一由 IT 团队管理公网资源和开通权限，禁止业务部门私自开通公网类型实例；客户需要通过安全合规的网络架构最大化保护企业内部服务，防止潜在的安全威胁；统一管理公网类型产品预算，同时最大化复用公网带宽资源，降低 IT 成本。因此需要设计统一公网出入口的网络（对标数据中心的 DMZ 区）。

**1、场景整体设计**

-   云上统一公网出入口（DMZ VRF），是新建一个 VRF，作为隔离外部互联网（非信任区域）和企业云上内网（信任区域）之间的一个接入接出区域。一方面，统一公网出入口设计，集中管理了公网接入接出资源，便于构建高并发大流量的应用接入网关、管理企业外联访问控制、合理利用公网带宽资源。另一方面，通过和安全产品结合，可以确保企业内网得到最大程度的保护。
    

**2、核心路由器及路由表设计**

-   有公网出入口的业务 VRF 和 DMZ VRF 都挂载到核心
    
-   核心使用系统路由表（默认）。路由表中配置自定义路由 0.0.0.0/0、下一跳到 DMZ VRF，将出公网的流量引入到 DMZ VRF 进而出公网；公网入的流量经过 NAT 和防火墙目的 IP 转换成私网地址后查此路由表的明细路由转发到目的 VRF
    

**3、DMZ VRF 设计**

-   SLB 子网：划分独立的 SLB 子网（Public 子网），部署负载均摊设备；每个设备多可用区部署提升可靠性
    
-   NAT 子网：划分独立的 NAT 子网（Public 子网），部署 NAT 实例；有出公网需求的业务 VLAN 同可用区部署独立 NAT 实例，以便于在可用区故障时不影响其他可用区的 NAT 出网流量
    
-   IPv4 网关：统一管控公网入口
    
-   公网带宽：1）共享带宽包支持按带宽预付费、按带宽后付费、按带宽 95 计费、按流量计费，共享带宽 EIP 共享总带宽并受限速；2）直连公网支持按流量计费，享受阶梯价格
    

**4、安全防护设计【可选】**

-   公网入云防护：推荐使用互联网边界防火墙
    
-   公网出云防护：服务器自带公网 IP、EIP 推荐使用互联网边界防火墙；NAT 出公网推荐使用 NAT 边界防火墙，可以使用 VPC 边界防火墙
