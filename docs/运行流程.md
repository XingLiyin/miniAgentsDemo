一、Session 创建（SessionManager.create_session）

1. 创建 Session 对象（持久化到存储），携带：

   * goal
   * token_budget
   * root_max_turns

2. 根据 template_id（或 default template）创建 root Agent，写入：

   * soul_md（Actor 用，执行人格）
   * role_md（Observer 用，评判准则）
   * tool_list
   * skill_list
   * soul_path

3. 调用 task_svc.create_plan_task，创建第一个 task：

   * type = plan
   * use_subagent = True

4. LifecycleManager.init_session 初始化 per-session 运行时状态：

   * 并发计数
   * agent 注册表

---

二、调度启动（SessionManager.schedule_loop → LifecycleManager）

schedule_loop 找到第一个 PENDING task，交给 LifecycleManager.schedule_initial_task。

由于 plan task 带 use_subagent = True：

* LM 调用 _auto_spawn_for_task，从 parent agent 配置实例化一个 plan sub-agent
* plan sub-agent 继承：

  * soul_md
  * role_md
  * tool_list
  * skill_list
  * 若 inherit_memory = True，则复制记忆
* 注册到 agent_registry，并在 daemon worker thread 中执行

---

三、单次 Task 执行（AgentLoop.run）

每个 task 独立执行三个阶段：Reasoner → Actor → Observer

3.1 前置检查

* 检查 token_budget 是否耗尽
* 检查 guard.turns_used 是否超过 max_turns
* task 状态从 PENDING → ACTIVE

3.2 Reasoner：构建上下文（无 LLM 调用）

ctx = reasoner.reason(session, agent, task)

由 task.type 决定加载资源：

plan task：

* skill_resources

  * 从 skill store 搜索（或 agent.skill_list 全量）
  * 返回 ContextResource(kind = "skill")

* tool_resources

  * AgentController.get_llm_schemas(scope = "planner")
  * 包含 submit_plan 工具

* Memory

  * memory_svc.get_window(agent_id)：最近对话窗口
  * memory_svc.get_summary(agent_id)：摘要

* Blackboard

  * blackboard_svc.pull(session_id, "_root", agent_id)

act / atomic task：

* tool_resources

  * 从 tool store 搜索（或 agent.tool_list 全量）
  * * AgentController.get_llm_schemas(scope = "actor")
  * 如 request_human_input 等

* Memory、Blackboard 同上

输出 ReasoningContext：

* goal
* recent_messages
* summary_text
* blackboard_snippets
* soul
* role
* skill_instructions
* resources: list[ContextResource]
* current_task
* token_estimate

3.3 Actor：LLM tool-use 循环

result = actor.act(task, ctx, agent)

System prompt 组装（_build_system_prompt）：

* ctx.soul（Agent 身份与执行协议，SOUL.md）

---

* _build_resources_section()

  * skills → "## Available Skills: ..."
  * tools → "## Available Tools: ..."

---

* ctx.skill_instructions（可选，当前 skill 的操作指南）

User 消息组装（_build_messages，仅在循环前执行一次）：

* message[0]：

  * goal
  * 若存在 summary_text，则前置：
    "Previous progress:\n..."

* message[1]：

  * "Context:\n{blackboard_snippets}"（若存在）

* message[2..]：

  * ctx.recent_messages（memory window，逐条追加）

Tool-use 循环（最多 actor_max_tool_rounds 轮）：

每轮执行：

1. 发送 messages（含 system prompt）+ tools 给 LLM

2. 解析响应：

   * 无 tool call
     → 保存 LLM 文本
     → 退出循环（act 完成信号）

   * 有 tool call
     → 逐个分发：

     * 若 AgentController.can_handle
       → 内部处理（submit_plan、request_human_input 等）
       → 若返回 ControlSignal.TASK_COMPLETE，则 done = True

     * 否则
       → ToolGateway.call（外部工具）

3. _append_tool_turn

   * 将工具结果作为 role = "user" 消息追加到 messages
   * 供下一轮 LLM 使用

输出 ActorResult：

* tool_calls_made
* conversation_turns（每轮完整记录）
* output（最终文本）
* actor_mode

3.4 Observer：独立 LLM 评估

verdict = observer.observe(session, result, ctx, task)

* plan 模式

  * 规则降级（不调用 LLM）
  * 空计划 → done = True
  * 有 task → done = False

* act 模式

  * 使用独立 LLM 调用

Observer system prompt：

* ctx.role（ROLE.md 或 fallback）

---

* _OBSERVER_EVALUATION_GUIDE（固定方法论）

Observer user 消息结构：

* Original session goal: ...

* Previous progress summary: ...

* Current task / Task description: ...

* Execution transcript：
  --- Round 1 ---
  Tool call: xxx({args})
  Result [OK]: ...
  Agent reply: ...
  ...

* Evaluate: did the agent complete the current task?

LLM 通过调用 submit_observation 工具返回：

* task_complete
* task_result
* done
* summary
* reasoning
* needs_user_confirm
* spawn_planner

---

四、Task 完成后处理（AgentLoop）

* 根据 verdict.task_success：

  * 调用 task_svc.finish 或 task_svc.fail

* 将 verdict.summary 写入 agent memory：

  * role = "assistant"

* 将 conversation_turns 发布到 blackboard

* 若 memory_svc.should_summarize(agent_id)：

  * 触发记忆压缩（_do_summarize）

* 若 verdict.done = True：

  * session_svc.transition("SUCCEEDED")

---

五、调度下一个 Task（LifecycleManager._on_agent_finished）

Agent 完成后发布 AGENT_FINISHED 事件：

* root agent：

  * 调用 task_svc.list_pending(session_id)
  * 若存在 pending tasks → 继续调度
  * 若不存在 → task_manager.create_replan

    * 创建新的 plan task，继续循环

* sub-agent：

  * 回收自身
  * root agent 继续处理后续 pending tasks

---

总结：上下文给到 LLM 的结构

System prompt：

* [SOUL.md]：执行身份 + Tool Protocol
* [Resources]：Available Skills / Available Tools
* [Skill guide]：（可选）当前 skill 操作指南

User messages：

* goal (+ summary)：会话目标 + 历史摘要
* context（blackboard）
* recent_messages（最近 N 条 memory 对话）
* tool results（每轮工具结果，动态追加）
