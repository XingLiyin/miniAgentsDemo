● miniAgents 调度逻辑总览                                                                                                                            
                                                                                                                                                     
  架构分层                                                                                                                                           
                                                                                                                                                     
  SessionManager   创建 Session / Agent / Task，通知 TM 启动                                                                                         
      ↓                                                                                                                                              
  TaskManager      task 调度决策层（订阅事件，驱动整个生命周期）
      ↓                                                                                                                                              
  TaskQueue        per-session LIFO 栈 + blocked 集合（dep-aware）
      ↓
  LifecycleManager agent tree 管理（装配、回收、执行）
      ↓
  AgentLoop        单次 task 执行（LLM 推理 + 工具调用）

  ---
  一、Session 启动

  SM.create_session
    ├─ 创建 Session + root Agent
    ├─ LM.init_session + register_root_agent
    ├─ TM.init_session          ← 初始化 TaskQueue（必须在 task 创建前）
    └─ SM._create_initial_task  → task_svc.create(PENDING)
                                 → TASK_CREATED 事件 → TM.on_task_created → push 入栈

  SM.schedule_loop
    └─ TM.start_session
         ├─ session QUEUED → RUNNING
         └─ task_queue.pop() → _dispatch_next → LM

  ---
  二、TaskQueue 入栈时机

  ┌───────────────────────┬─────────────────────────────────────┐
  │         时机          │                触发                 │
  ├───────────────────────┼─────────────────────────────────────┤
  │ task 被创建           │ TASK_CREATED 事件 → push            │
  ├───────────────────────┼─────────────────────────────────────┤
  │ 父任务 SUSPENDED 恢复 │ _try_resume_parent resume 后 → push │
  ├───────────────────────┼─────────────────────────────────────┤
  │ 失败任务重试          │ on_task_failed retry 后 → push      │
  └───────────────────────┴─────────────────────────────────────┘

  push 规则：dag_deps 全 terminal → 入 _ready 栈；否则入 _blocked 集合。

  ---
  三、_dispatch_next（TM → LM 唯一通道）

  task_svc.transition(next_task, ACTIVE)

  agent_id = LM.prepare_executor(finished_agent_id, task_id, use_subagent, ...)
    _settle_executor:
      finished 是 sub-agent → 回收它，executor = root
      finished 是 root      → executor = root（自身）
    use_subagent = False → 返回 executor
    use_subagent = True  → 检查 spawn 权限
      通过 → 创建 sub-agent（parent_id = executor），写入 registry
      拒绝 → 降级 inline，返回 executor

  LM.run_agent(agent_id, task_id)
    → daemon thread → LM._execute → AgentLoop.run

  daemon agent（metadata 生成等）：不入 LM registry，_execute 完成后不发布事件，TM 感知不到。

  ---
  四、AgentLoop 内的控制流

  agent 通过 control tools 推进调度：

  ┌────────────────────────────────────────┬──────────────────────────────────────────────────────────────────────────────────────────────────────┐
  │                  工具                  │                                                 效果                                                 │
  ├────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ submit_plan([A,B,C])                   │ 创建 dag_deps 链（B依赖A，C依赖B）→ 父任务 SUSPENDED → 子任务入栈依次执行 →                          │
  │                                        │ 所有子任务完成后父任务恢复，LLM 评估收尾                                                             │
  ├────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ submit_task(X)                         │ 创建单个子任务 → 父任务 SUSPENDED → 子任务完成后父任务恢复，agent 继续执行                           │
  ├────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ submit_task_assessment(success/failed) │ 标记当前 task 完成状态 → AgentLoop 结束本轮                                                          │
  ├────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────────────────────┤
  │ replan(...)                            │ 取消所有 PENDING tasks → 创建新 plan task                                                            │
  └────────────────────────────────────────┴──────────────────────────────────────────────────────────────────────────────────────────────────────┘

  ---
  五、Task 完成后续接

  LM._execute 完成 → 发布 TASK_EXECUTION_FINISHED

  TM.on_task_finished
    ├─ record_success
    ├─ [session lock]
    │    task_queue.notify_completed(finished_task_id)
    │        → 将 blocked 中 deps 现已满足的 task 升入 _ready 栈
    │    _try_resume_parent(finished_task_id)
    │        → 若父任务 SUSPENDED 且所有子任务 terminal
    │            → task_svc.resume(parent) → task_queue.push(parent)
    │    task_queue.pop() → next_task
    │    next_task = None + is_empty() → session SUCCEEDED
    │    next_task = None + has_work() → deps 等待中，暂不调度
    └─ _dispatch_next(agent_id, next_task)

  失败路径对称：task_svc.fail → 重试则 push 回栈，超限则找下一个或 session FAILED。

  ---
  六、执行顺序保证

  - submit_plan 内部顺序：dag_deps 链（B blocked 直到 A terminal），notify_completed 逐步升栈，LIFO 不影响顺序（每次只有一个就绪）
  - sub-task 优先于兄弟 task：LIFO 栈，子任务入栈顶，深度优先执行
  - daemon task 不干扰主流程：不入 registry，完成不发事件，session 状态不受影响
